# 求职打招呼语生成工作流

## 概述

读取 JD 与个人经历材料（简历 / 项目笔记），做匹配分析后生成可直接发送的打招呼语。

**核心能力：**
- 证据分级的匹配分析：按「商业交付 > 自研项目 > 学习项目」「交付物与 JD 职责直接对应 > 技术栈相似」「数字 > 形容词」排序，只突出最匹配项，其余一句带过
- 双版本输出：主推版（约 100-130 字）+ 超短版（约 70-80 字），覆盖不同平台字数限制
- 联网核查平台最佳实践，标准沉淀在 `references/greeting-principles.md`
- 输出附带调整逻辑说明，用户可基于理由自行微调

## 输入要求

**JD（必需）：** 粘贴文本，或给出文件路径。岗位职责和任职要求都要，缺一可提示补全但不阻塞。

**经历材料（必需）：** 三种来源，按优先级：
1. 用户明确指定的经历文件（如「这段经历相关」并给出路径）→ 以用户指定为准，只基于指定材料生成
2. 用户提供了简历路径 → 解析 `## 专业技能` / `## 工作经历` / `## 项目经历`
3. 都没有 → 询问简历或相关项目笔记的位置

## 核心原则

1. **证据先行，不断言**：开头用「交付过什么」的事实开场，禁止「我和岗位高度匹配」式开头断言——匹配靠证据展示，不靠自我声明（依据见 `references/greeting-principles.md`）
2. **最匹配项前置**：一封打招呼语只强调一个最强证据，其余经历压缩成半句或省略
3. **匹配断言只放结尾**：惯用句式「和您的招聘要求很匹配」放在结尾收尾，顺势接行动请求
4. **JD 关键词回显**：JD 中的岗位核心词（如「Claude Code」「全周期」「稳定性」）在打招呼语中原样出现
5. **术语为 HR 降维**：读者是不懂技术细节的 HR，删掉内部术语（框架名、协议名、文件名），领域词翻译成业务语言（如「AUTOSAR 嵌入式 C」→「汽车电子团队」）
6. **不虚报**：没有经历支撑的年限、规模、成果不写；JD 要求「1-3 年经验」但材料只有更短经历时不主动提年限，用项目密度撑说服力
7. **明确行动引导**：结尾以行动请求收束（「方便发您一份完整简历吗」），不问 JD 里已有的信息（薪资、职责）

## 工作流

### 第一步：收集 JD 与经历材料

按「输入要求」获取 JD 和经历材料。向用户确认解析结果：

```
JD 岗位要点：<3-5 条关键词摘要>
经历材料：<文件列表或粘贴内容摘要>
最匹配项初步判断：<一句话>
确认生成打招呼语？
```

### 第二步：匹配分析

1. 把 JD 逐条拆成「职责」和「要求」两类条目
2. 扫描经历材料，为每条 JD 条目找对应证据，按 `references/greeting-principles.md` 的证据强度排序
3. 选出**唯一最匹配项**（最强证据），再选 1-3 个次级匹配点（各留一个短语即可）
4. 特别注意：JD 某条职责与经历材料中某个交付物**直接同构**时（如 JD 要「输出技术文档」，经历恰以技术文档为交付物），这是最硬的对应点，必须进打招呼语

### 第三步：联网核查平台最佳实践（默认执行）

用 WebSearch 搜索当前目标平台的打招呼语技巧（如「Boss直聘 打招呼语 最佳实践」「求职打招呼 回复率 技巧」），提炼要点，重点确认：主流开头写法、推荐字数、「匹配」类表述的惯用位置、常见无效模板。要点记入输出末尾的「依据」区，附来源链接。用户要求跳过联网或环境无网时，直接使用 `references/greeting-principles.md` 的沉淀标准。

### 第四步：生成打招呼语

按 `references/greeting-templates.md` 的模板生成两版：

- **主推版**：约 100-130 字，结构 = 证据钩子 → 次级匹配点（1-3 个短语）→ 差异化条件（兼职/到岗）→ 匹配收尾 → 行动请求
- **超短版**：约 70-80 字，砍掉次级匹配点细节，保住证据钩子和行动请求

写完后逐条过自检清单（见下），不达标就改写而不是解释。

### 第五步：输出

输出格式：

```
## 主推版（约 N 字）

<打招呼语正文>

## 超短版（约 N 字）

<打招呼语正文>

## 调整逻辑
- 强调了什么、为什么（对应 JD 第几条 + 证据强度）
- 简写或省略了什么、为什么
- 刻意没写什么（年限/术语/断言）及原因

## 依据（联网搜索时）
- <要点> — <来源链接>
```

## 自检清单

生成后逐条核对，任一不满足则改写：

- [ ] 开头第一句是事实证据，不是兴趣声明或匹配断言
- [ ] 只有一个强调点，其余经历不超过半句
- [ ] JD 至少 2 个关键词原样出现
- [ ] 无内部术语，无英文技术栈缩写堆砌（岗位本身就是该技术时除外，如 Claude Code）
- [ ] 「匹配」类表述只出现在结尾
- [ ] 有明确的行动请求
- [ ] 未出现 JD 已有信息的提问
- [ ] 未虚报年限、规模、成果
- [ ] 主推版 ≤ 130 字，超短版 ≤ 80 字

## 参考文件

- `references/greeting-principles.md` — 写作标准与平台最佳实践沉淀（证据分级、结构公式、禁止清单、发送时机）
- `references/greeting-templates.md` — 版本模板与真实案例（主推/超短/自研钩子变体/跟进消息，含改前改后对照）

## Roadmap

本技能是 outreach 插件自动化的第一步。后续规划：

1. **auto-greet**：对接招聘平台 API 或浏览器自动化，按本技能标准批量生成并发送打招呼语
2. **send-resume**：打招呼通过后自动投递简历附件
3. **reply-tracker**：跟踪已读/回复状态，对已读不回的会话按 `greeting-templates.md` 的跟进模板定时跟进

本技能的输出（两版打招呼语 + 调整逻辑）即为上述自动化的消息内容输入，标准变更只需改 references 文件。
