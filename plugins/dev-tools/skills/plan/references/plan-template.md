### 任务级可选字段触发表

必填仅三项：`任务`、`描述`、`验收标准`。其余字段**只有命中触发条件才写**；写了就要短，宁缺毋滥。

| 可选字段 | 何时写 |
|----------|--------|
| **目录/模块结构** | 新建模块 / 跨层改动 / 目录约定不直观 |
| **数据结构** | 引入新实体、状态机状态、持久化 schema、跨任务共享类型 |
| **接口契约** | 任务产出会被后续任务消费，或对外暴露 API / CLI / 事件 |
| **逻辑概要** | 状态机 / 调度 / 去重 / 冲突 / 权限分支 / 重试补偿 |
| **涉及文件** | 边界复杂、并行派发需锁文件、或高风险改动 |
| **验证方式** | 验收标准无法靠读代码一眼判定时 |
| **不做** | 容易越界改相邻模块，或与下阶段有明确分界时 |

原则：能显著降低实施歧义才写；不为模板完整性强行填满。

## 使用说明

此模板在 SKILL.md Step 5 中被加载。Claude 应：

1. 读取此模板了解详细计划的结构
2. 基于用户的架构约束文档（architecture.md / CLAUDE.md）填充第 2 章
3. 基于需求文档和总体计划填充第 3 章（任务列表）
4. 将每个任务直接写入详细计划文档中的 checkbox 列表，作为默认进度事实源
5. 先写“第一性原理定义”，再生成任务列表
6. 任务数量默认控制在 3-5 个/阶段；只有复杂阶段才放宽到 6-7 个
7. 高风险假设存在时才加入“最小可行性验证”任务
8. 任务级可选字段（目录/模块结构、数据结构、接口契约、逻辑概要、涉及文件、验证方式、不做）严格按触发表展开；图示、风险、开放问题同样按需输出，不要为了模板完整性强行填写
9. 简单任务可只保留任务 / 描述 / 验收标准 / 依赖；复杂任务至少补齐命中触发条件的 1-2 个可选字段
10. 任务、验收标准、测试场景、人工验证步骤统一使用 todo list；后续修改和进度展示都基于勾选状态
11. 不单独写显式进度百分比或阶段内进度描述；进度通过 checkbox 勾选状态间接体现
