## 二、Code Agent Prompt 模板

### 2.1 完整 Prompt 模板

构造 prompt 前，调用方或执行方必须已 Read `coding-rules.md`。

```
## 任务：<SLUG>-PN-NN: <标题>
（若无计划任务 ID，用简短标题即可）

根据详细计划文档 <plan-path> 中的此任务（若无计划则按下方任务描述直接实施）。

### 任务描述
<从计划中复制，或用户需求摘要>

### 验收标准
- [ ] <条件1>
- [ ] <条件2>

### 任务级可选项（仅复制计划中已写出的字段；未写则整段省略）
- **目录/模块结构**：<如有>
- **数据结构**：<如有>
- **接口契约**：<如有>
- **逻辑概要**：<如有>
- **涉及文件**：
  | 文件路径 | 操作 | 说明 |
  |----------|------|------|
  | <path> | 新增/修改 | <说明> |
- **验证方式**：<如有>
- **不做**：<如有>

### 前置依赖产出
<已完成任务的产出摘要，或 "None">

### 架构约束
<如果项目有约束文档，列出关键约束>

### 编码规则（必须遵守）

严格遵循 code-agent `references/coding-rules.md`：
1. 动笔前完成第一性原理四问（最小成果 / 落点 / 复用与封装 / 验证）并简要记录
2. 编码前对齐清单：同类实现、同类测试、lint/风格、依赖边界
3. 落点优先扩展现有模块；禁止无理由平行新树
4. 复用优先；仅在规则允许时封装
5. 注释 / 测试 / 风格按 coding-rules 第五、六章执行
6. 只改验收所需，不顺手扩 scope

### 完成后报告
1. 四问结论摘要（落点 / 复用 / 封装 / 验证）
2. 实际修改的文件（与预估的差异及原因）
3. 验收标准达成情况（逐条标记 [x]/[ ]）
4. 测试用例列表（todo 场景 + 覆盖哪种情况）或手工验证步骤
5. 已知限制或遗留问题
6. 若来自计划：已同步更新计划文档 checkbox（任务项、验收标准、已完成测试项）
```

### 2.2 并行派发时的补充说明

当一组无依赖任务并行派发时，在每个 agent prompt 末尾追加：

```
### 并行注意
此任务与以下任务并行执行：<列出其他并行的任务 ID>
请只修改你有权修改的文件，避免写入共享文件导致冲突。
```

## 三、代码实施验收

### 3.1 验收清单

- [ ] 验收标准逐条达成
- [ ] 实施前完成了 coding-rules 四问（报告中可见落点/复用/封装/验证）
- [ ] 落点与现有分层一致；无无理由平行目录
- [ ] 关键代码有注释（公共函数、复杂逻辑、非显而易见的决策）
- [ ] 核心逻辑有测试用例（Happy Path + 边界值 + 异常路径），或非核心改动有约定验证
- [ ] 修改的文件与预估一致（如有偏差，评估是否合理；若计划未列预估文件则跳过此项）
- [ ] 代码风格与项目现有模式一致（命名、错误处理、日志）
- [ ] 未引入未授权新依赖、未越过「不做」边界
- [ ] 若来自计划：对应 checkbox 已同步勾选

### 3.2 不通过处理

| 问题 | 处理方式 |
|------|---------|
| 未做落点/复用分析就开写 | 要求补四问结论；落点错误则重做 |
| 缺少注释 | 要求补充后重新提交 |
| 缺少测试（核心逻辑） | 必须补测 |
| 缺少测试（非核心） | 记录为待补，不阻塞流程 |
| 风格不一致 / 平行新树 | 指出差异，要求对齐现有模块 |
| 验收标准未达成 | 分析原因，调整任务描述或重新实施 |
| 越过「不做」或扩 scope | 回退无关改动后重交 |
